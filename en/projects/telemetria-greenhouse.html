The challenge

A greenhouse requires monitoring temperature, ambient humidity, light, and soil moisture, along with irrigation and ventilation actions. Historical analysis also requires defined schemas, quality checks, and reproducible data persistence.

Approach & contribution

The project began with the design and implementation of a greenhouse monitoring and control architecture as part of IoT studies (UTN, 2023–2024). I subsequently developed a data processing layer using Python and PySpark. The two phases share a domain and data model, but an automatic, continuous connection from the original physical system to the pipeline has not been established.

  • I designed the IoT architecture with DHT22, TSL2561, and capacitive soil-moisture sensors, ESP32, Raspberry Pi, MQTT/Mosquitto, Node-RED, and Blynk, with irrigation and ventilation actuators.
  • I modeled devices, zones, sensor and actuator events, and prepared simulated data and external historical weather information.
  • I implemented Python/PySpark Bronze → Silver batch pipelines with explicit schemas, separate readers and writers, and dataset-specific quality checks.
  • I persisted validated records to Parquet, added execution/error logging, and documented the modules and processing sequences.

What this demonstrates

The project combines an understanding of IoT hardware and communications with data modeling, PySpark processing, data-quality validation, logging, and modular software design. It demonstrates a technical progression from physical monitoring to preparing structured datasets for analysis.

Evidence & scope

The repository documents a Python/PySpark Bronze → Silver pipeline with previously verified execution and Parquet outputs. Its demonstration uses simulated sensor and actuator events, device/zone catalogs, and external historical weather information. The architecture builds conceptually on the earlier IoT system, but a continuous automatic connection between physical devices and the data pipeline has not been verified. The Gold layer and derived analytical indicators remain potential extensions. This is an academic and technical-portfolio project, not a commercially deployed system.
