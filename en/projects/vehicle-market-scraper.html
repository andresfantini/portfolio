Vehicle Market Scraper

Extraction of vehicle listings through a modular software architecture, avoiding individual access to each listing.

The challenge

A car dealership needed to analyze the used vehicle market, but manually extracting listings from Mercado Libre was unfeasible due to the volume and dynamic pagination. The objective was to build a horizontal scraper that would capture result cards en masse, normalize the data (prices, years, mileage), and avoid duplicates without entering each individual listing.

Approach & contribution

I designed the system as a staged processing flow with separated responsibilities: 1. HTTP Acquisition: Persistent session, cookies, and block detection (403/429). 2. Pagination: Automatic calculation of subsequent page URLs. 3. Crawler: Orchestrator of the crawl that manages the page limit and deduplication using unique identifiers (IDs). 4. Parser: Interpretation of the card HTML. 5. Normalization: Conversion of text (e.g., '130,000 Km') into numerical values ready for analysis. 6. Export: Generation of the dataset in CSV. Initial MVP validation was performed on a 2018 Volkswagen Up! search, obtaining 106 records with 0 duplicates.

HTTP acquisition and pagination → Parsing and normalization → Deduplication and export

What this demonstrates

The project demonstrates the ability to design maintainable software architectures (separating acquisition, parsing, and export), apply robust Web Scraping techniques against blocking, and develop automated tests with HTML fixtures to ensure analysis reproducibility without depending on the live site.

Evidence & scope

The MVP is functional and locally validated. A horizontal scraping approach (results pages only) was implemented to minimize load on the platform. Vertical scraping (entering each ad) is out of current scope. The code includes tests and technical architecture documentation.
